# SUNI 챗봇 수동 평가 15문항

`prompts/chat_system.md`/`prompts/report_system.md`와 `api/routes/chat.py`의 프롬프트 조립 로직을
바꿀 때마다, 실제 LLM 응답 품질은 `tests/test_chat_golden.py`(프롬프트 조립 결과만 검증하는 골든
테스트)가 잡지 못한다. 이 표는 사람이 챗봇을 직접 두드려 확인해야 할 15문항이다 — 질문 / 답에
반드시 들어가야 할 근거 / 나오면 안 되는 표현.

실행 조건: 원인 분석을 먼저 실행한 뒤(데이터셋 `train` 기준), 아래 순서대로 하나의 대화창에서 이어서
질문한다(15번은 6턴째 질문이므로 반드시 이어서 진행해야 검증된다).

| # | 등급 | 질문 | 답에 반드시 들어갈 근거 | 나오면 안 되는 표현 |
|---|---|---|---|---|
| 1 | digest | 가장 신뢰도 높은 인자는 무엇인가요? | `targets[].factors[0]` 중 신뢰도가 가장 높은 인자명과 근거(설명력 등) | `eps2`/`report_confidence` 같은 JSON 필드명 노출 |
| 2 | full | Step28_R1은 Y1에 어떤 영향을 주나요? (실제 존재하는 인자명으로 대체) | 관계 형태(단조/U자), 설명력, 권장 구간(있으면) | "때문에"/"원인이다" 같은 인과 단정 |
| 3 | full | (알람 목록에 실제로 있는 wafer ID) 알람이 왜 떴어? | 벗어난 인자·측정값·관리한계·이탈 방향, 신뢰도 등급 | 알람 목록에 없는 wafer를 지어내 답하기 |
| 4 | digest | 이 분석의 한계는 무엇인가요? | `limitations[]`의 문장을 그대로 또는 풀어서 인용 | `limitations`에 없는 한계를 새로 만들어내기 |
| 5 | none | 예측 구간이 왜 이렇게 넓나요? | conformal 방식·목표 포함률 90%, 데이터 설명력 한계라는 서술 | 고정된 "±5.5%p" 같은 수치를 이번 분석 값처럼 단정 |
| 6 | digest | 왜 알람이 없나요? (알람 0건인 경우) | `summary`의 관련 카운트 또는 상관성 등급 조건(FDR 미통과·효과크기 미달·계측 부족)을 근거로 추론 | "알람이 없으니 정상입니다"로 단정 |
| 7 | none | 이 화면은 무엇을 보여주나요? | 현재 탭(예: 원인 분석)의 구성 요소를 "대시보드 기능 안내" 근거로 설명 | 이번 분석의 구체 수치를 지어내어 섞기 |
| 8 | none | 민감도를 올리면 무엇이 달라지나요? | 그 컨트롤은 더 이상 쓰이지 않으며 지금은 예측 수율 순위·신뢰도(n/5)로 판단한다는 안내 | 슬라이더가 여전히 있다는 듯한 동작 설명 |
| 9 | none | 심각·위험·주의는 어떻게 나뉘나요? | 그 등급 체계는 더 이상 쓰이지 않으며 지금은 순위+신뢰도(n/5)로 판단한다는 안내 | 컷 공식(예: "4.0%p", "0.8%p" 간격)을 지어내 설명 |
| 10 | digest 또는 none | 수율 변동은 어느 불량모드에서 오나요? | 웨이퍼 간 편차 기여(cov/var 기반, train.CSV 실측 기준)라는 설명, "평균 손실 비중과 다르다"는 구분 | 평균 손실이 가장 큰 불량모드로 잘못 답하기 |
| 11 | none | 계측이 없는 웨이퍼는 어떻게 처리되나요? | 신뢰도 0인 wafer는 순위 목록과 분리해 "미계측" 묶음으로 뺀다는 설명 | 자동으로 알람 처리된다는 등 없는 동작 서술 |
| 12 | none | 알림은 언제 발송되나요? | 알림 기록 탭에서 과거 발송 이력을 확인할 수 있다는 안내 | 존재하지 않는 고정 발송 시각/조건을 창작 |
| 13 | (후속) | (11번 답변 뒤) 방금 답 요약해줘 | 직전 답변 내용을 반영한 짧은 요약 | 보고서 형식(6개 섹션)으로 처음부터 새로 작성 |
| 14 | report | 분석 보고서 만들어줘 | `report_system.md`의 6개 섹션 구조, `_text` 필드 인용 | 숫자를 새로 계산하거나 인과를 확정하는 문장 |
| 15 | full (6턴째) | (2번에서 물은 인자명)에 대해 다시 설명해줘 — 대화 시작 후 최소 6번째 질문이어야 한다 | 2번 답변과 일치하는 정확한 수치(설명력·신뢰도 등)를 여전히 근거로 제시 | "정보가 없습니다"로 답하거나 2번과 다른 수치 제시(A-1이 고친 4턴째 근거 소실 회귀 확인용) |

## 채점 방법

- 각 문항을 "근거 포함 / 금지 표현 없음" 둘 다 만족하면 통과로 표시한다.
- 15번이 실패하면(6턴째부터 근거를 잃으면) A-1의 회귀다 — `HISTORY_TURNS`(백엔드)와
  `HISTORY_MESSAGES`(프런트)가 실제로 같은 값인지, `_grounding_block`이 매 턴 `system` 메시지로
  붙는지 먼저 확인한다.
- 8·9·11번이 실패하면(죽은 판정 체계를 되살려 답하면) `prompts/chat_system.md`의 "수율 예측 탭"
  절이 실제 배포된 프롬프트에 반영됐는지 확인한다(캐시: `_chat_system_prompt`는
  `@lru_cache`이므로 서버 재시작이 필요할 수 있다).
